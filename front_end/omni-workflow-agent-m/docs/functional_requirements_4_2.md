## 4.2 功能需求

本项目围绕移动端智能工作流处理场景进行设计，系统功能需求以统一入口、多模态输入、连续处理、历史沉淀和个性化配置为核心。结合当前代码仓库中的前端页面、后端路由与服务逻辑，可将系统归纳为五个核心功能，并分别通过“核心功能模块描述表”和“用例规约表”进行说明。

### 4.2.1 功能模块

**表1 主界面导航与任务触发模块描述**

| 功能模块 | 功能 | 功能描述 | 优先级 |
| --- | --- | --- | --- |
| 主界面导航与任务触发模块 | 页面切换与任务触发 | 系统通过顶部导航在首页、工作流和历史页面之间切换，并由首页能力项、录音入口和新建工作流操作触发后续任务处理。 | 高 |

**表2 主界面导航与任务触发用例规约**

| 项目 | 内容 |
| --- | --- |
| 用例名称 | 主界面导航与任务触发 |
| 功能简述 | 用户通过顶部导航切换系统主页面，并通过首页能力项、录音入口或新建工作流操作发起任务处理。 |
| 用例编号 | UC-01 |
| 执行者 | 普通用户 |
| 前置条件 | 用户已进入系统主界面；顶部导航、页面切换和首页触发能力正常可用。 |
| 后置条件 | 系统完成页面切换或任务触发，并在需要时进入新的工作流会话。 |
| 涉众利益 | 用户希望在首页、工作流、历史之间快速切换，并能以较低操作成本发起新任务；系统希望将主要交互收敛到稳定的主界面结构中。 |
| 基本路径 | 1. 用户进入系统主界面。<br>2. 用户通过顶部导航切换首页、工作流或历史页面。<br>3. 用户在首页选择能力项、录音入口，或在导航区触发新建工作流。<br>4. 系统根据用户操作切换页面或重置当前会话。<br>5. 系统将用户带入工作流页面并准备后续任务处理。 |
| 扩展路径 | 1. 若用户直接停留在工作流页面，则系统不经过首页触发步骤。<br>2. 若首页录音入口调用失败，则系统提示用户重新尝试。<br>3. 若用户从历史页面打开旧会话，系统直接进入对应工作流内容。 |
| 字段列表 | 用户ID、会话ID、消息内容、工作流模式、会话标题。 |
| 设计规则 | 主界面应以顶部导航为核心组织结构；首页负责任务触发而非独占全部入口；新建任务、打开历史和首页触发应能收敛到统一工作流页面。 |
| 未解决的问题 | 首页能力项与后续任务模板之间的映射关系仍可进一步细化；主界面中的门户区与任务触发区边界还可继续优化。 |
| 备注 | 该功能体现系统以主界面为中心组织页面切换与任务触发的设计逻辑。 |

**表4 工作流处理用例规约**

| 项目 | 内容 |
| --- | --- |
| 用例名称 | 工作流任务处理 |
| 功能简述 | 用户在工作流界面中提交任务内容，系统完成处理、生成结果并在会话中连续展示。 |
| 用例编号 | UC-02 |
| 执行者 | 普通用户 |
| 前置条件 | 用户已进入工作流界面；工作流服务和会话管理功能可正常使用。 |
| 后置条件 | 当前会话中生成新的用户消息块和AI结果块，并保存到系统中。 |
| 涉众利益 | 用户希望获得连续、清晰、可追溯的任务处理体验；系统希望形成完整闭环并沉淀工作流结果。 |
| 基本路径 | 1. 用户进入工作流界面。<br>2. 用户输入任务内容并提交。<br>3. 系统创建或定位当前会话。<br>4. 系统保存用户输入内容。<br>5. 系统调用处理能力生成结果。<br>6. 系统在工作流界面展示处理结果。<br>7. 系统保存会话内容并更新历史记录。 |
| 扩展路径 | 1. 若当前无活动会话，系统自动创建新会话。<br>2. 若生成处理失败，系统提示用户稍后重试。<br>3. 若用户对最后一轮内容进行编辑，系统重新生成对应结果。 |
| 字段列表 | 会话ID、消息块ID、消息角色、消息内容、任务状态、会话标题。 |
| 设计规则 | 工作流处理应围绕会话展开；上下文内容应持续可见；用户输入和系统输出应成对组织；处理结果应可继续编辑和追踪。 |
| 未解决的问题 | 当前部分生成链路仍存在 mock 支撑；复杂任务下的长链路状态管理还可进一步优化。 |
| 备注 | 该功能为系统的核心主业务链路。 |

**表6 多模态输入用例规约**

| 项目 | 内容 |
| --- | --- |
| 用例名称 | 多模态输入处理 |
| 功能简述 | 用户通过文本、文件或语音提交任务信息，系统完成采集、上传、转写或整理后接入工作流。 |
| 用例编号 | UC-03 |
| 执行者 | 普通用户 |
| 前置条件 | 用户已进入工作流页面；设备录音权限、文件选择能力及相关接口均可正常使用。 |
| 后置条件 | 输入内容被系统成功采集并转换为可参与工作流处理的数据。 |
| 涉众利益 | 用户希望在移动端灵活选择输入方式；系统希望提高任务信息接入的完整性和便利性。 |
| 基本路径 | 1. 用户选择文本输入、文件上传或语音录入方式。<br>2. 系统接收对应输入内容。<br>3. 若为文件输入，系统完成文件上传并生成文件引用。<br>4. 若为语音输入，系统完成音频上传并执行转写或长音频任务创建。<br>5. 系统将处理结果接入当前工作流会话。 |
| 扩展路径 | 1. 若文件上传失败，系统提示用户重新上传。<br>2. 若短录音转写失败，系统给出失败提示或降级结果。<br>3. 若长音频处理时间较长，系统通过异步任务状态持续反馈进度。 |
| 字段列表 | 消息内容、文件引用、音频资源ID、转写文本、任务状态、工作流模式。 |
| 设计规则 | 不同输入方式应统一进入同一工作流链路；上传与转写过程应有状态反馈；长任务应采用异步处理方式。 |
| 未解决的问题 | 不同文件格式的深度解析能力仍有待增强；长音频处理时延在真实环境下仍需进一步验证。 |
| 备注 | 该功能体现系统的多模态接入能力，是移动端场景的重要特点。 |

**表8 历史会话管理用例规约**

| 项目 | 内容 |
| --- | --- |
| 用例名称 | 历史会话管理 |
| 功能简述 | 用户在历史页面查看和管理已完成或已保存的工作流会话，并对其进行继续使用或整理。 |
| 用例编号 | UC-04 |
| 执行者 | 普通用户 |
| 前置条件 | 系统中已存在历史会话数据；历史列表与会话存储功能正常。 |
| 后置条件 | 用户完成历史会话的查看、打开、整理或分享操作，系统同步更新记录状态。 |
| 涉众利益 | 用户希望快速回顾并复用已有任务成果；系统希望形成可沉淀、可追溯的工作流记录库。 |
| 基本路径 | 1. 用户进入历史页面。<br>2. 系统展示历史会话列表。<br>3. 用户选择目标会话。<br>4. 用户执行打开、搜索、重命名、删除、置顶或分享操作。<br>5. 系统保存变更结果并刷新历史列表。 |
| 扩展路径 | 1. 若目标会话不存在，系统提示数据异常。<br>2. 若删除或重命名失败，系统提示用户重新操作。<br>3. 若分享失败，系统提示当前会话暂不可导出。 |
| 字段列表 | 会话ID、会话标题、预览文本、任务状态、消息内容。 |
| 设计规则 | 历史会话应支持快速检索与恢复；重要操作应保持状态一致；会话打开后应恢复上下文内容。 |
| 未解决的问题 | 历史搜索精度、跨设备同步与更细粒度的归档能力仍可继续增强。 |
| 备注 | 该功能体现系统的信息沉淀和结果复用能力。 |
