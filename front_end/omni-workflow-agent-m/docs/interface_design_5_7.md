## 5.7 接口设计

本节围绕系统在运行过程中涉及的接口关系进行说明，重点阐述系统与外部资源之间的调用关系，以及系统内部前端模块、服务层、后端接口域之间的协作方式。内容以当前项目仓库中的前端 API 层、前端服务层、后端路由和接口文档为依据，突出接口职责、调用关系和前后端协同机制。

### 5.7.1 外部接口

系统外部接口包括软件接口和硬件接口两类。

#### （1）软件接口

1. 云端模型服务接口  
   云端模型服务接口用于提供复杂文本处理、长上下文推理和高质量内容生成能力。在系统中，该类接口承担复杂任务补充计算能力的角色，为工作流处理模块提供扩展生成支撑。

2. 本地模型服务接口  
   本地模型服务接口用于承接本地推理和语音识别能力，典型场景包括本地文本处理与语音转写。该类接口与后端服务协同，为系统提供相对独立的模型能力支撑。

3. PostgreSQL 数据接口  
   PostgreSQL 作为系统的结构化数据存储接口，用于保存用户信息、偏好配置、历史记录、工作流会话及相关业务数据。后端通过数据访问层与 PostgreSQL 交互，完成数据写入、读取和更新。

4. ChromaDB 向量接口  
   ChromaDB 作为语义向量存储接口，用于支撑后续语义检索和语义上下文扩展能力。该接口属于底层数据支撑接口，不直接暴露给前端，而由后端统一调用。

#### （2）硬件接口

1. 麦克风接口  
   系统通过 `expo-audio` 调用移动端麦克风能力，实现短录音与长录音采集。该接口主要服务于多模态输入模块和工作流语音输入链路。

2. 文件访问接口  
   系统通过 `expo-document-picker` 调用本地文件选择能力，实现文档文件上传。该接口用于接入用户本地资料并传入工作流处理模块。

3. 相机与图库接口  
   系统通过 `expo-image-picker` 调用相机和图库能力，实现图片采集与图片文件输入。该接口用于补充多模态输入方式，丰富移动端数据来源。

4. 本地存储接口  
   系统通过 `AsyncStorage` 调用移动端本地存储能力，用于保存认证状态、当前会话、历史摘要、主题设置和用户偏好等数据。该接口是系统本地缓存机制的重要组成部分。

5. 系统分享接口  
   系统通过 `Share.share` 调用移动端系统分享能力，用于导出工作流结果或历史会话内容。该接口主要服务于历史管理和结果分发场景。

### 5.7.2 内部接口

系统内部接口主要包括前端页面与服务层接口、前后端 REST 接口以及后端内部业务接口。

#### （1）前端页面与服务层接口

前端页面与服务层接口用于组织各页面之间的状态传递和业务调用关系。

1. 主界面布局接口  
   `MainLayout` 负责调用 `SessionManager` 管理当前会话状态，调用分享服务处理结果分享，同时组织首页、工作流页和历史页的切换与联动。

2. 工作流页面接口  
   `workflow.tsx` 通过 `workflow-api` 调用后端工作流接口，并调用 `Workflow_Storage`、`History_Storage`、`Workflow_Upload` 等服务完成会话缓存、历史更新、附件上传和录音处理。

3. 历史页面接口  
   `history.tsx` 调用 `History_Storage` 管理历史会话列表，调用 `SessionManager` 切换目标会话，并调用分享服务完成历史结果导出。

4. 认证页面接口  
   `auth.tsx` 调用 `auth-api` 完成验证码发送、登录、注册、密码重置和退出登录等认证操作，并通过本地存储维护登录状态。

5. 个性化配置页面接口  
   `personal.tsx` 调用 `personal-api` 完成用户偏好读取与保存，并通过本地存储实现本地优先回显和服务端同步。

#### （2）前后端 REST 接口

前后端 REST 接口是手机端与服务端交互的核心通道，统一以 HTTP/JSON 方式进行调用，并采用统一响应格式：

- 成功：`{ code: "0", message: "ok", data: ... }`
- 失败：`{ code: "ERR_xxx", message: "...", details?: {...} }`

主要接口域如下：

1. `/auth` 接口域  
   负责验证码发送、验证码登录、密码登录、注册、密码重置和退出登录。

2. `/user` 接口域  
   负责用户个性化偏好配置的读取与保存。

3. `/history` 接口域  
   负责历史会话摘要的读取、创建、删除、重命名和置顶状态切换。

4. `/portal` 接口域  
   负责门户日历数据和单日数据的读取、写入与删除。

5. `/workflow` 接口域  
   负责工作流会话详情获取、用户输入提交、AI 结果生成、文件上传、音频上传、语音转写、长音频任务创建和任务状态查询。

这些接口域共同构成了前后端协同的统一服务入口。

#### （3）后端内部接口

后端内部接口用于组织路由、数据结构、业务服务和数据访问之间的调用关系。

1. 路由挂载接口  
   `main.py` 作为统一服务入口，挂载 `auth`、`user`、`history`、`portal` 和 `workflow` 五类路由域，对外提供统一 API 服务。

2. 路由与数据结构接口  
   各路由模块通过对应的 `schemas` 定义请求和响应结构，用于约束前后端交互数据格式，保证接口输入输出一致。

3. 路由与业务服务接口  
   路由在接收请求后，将数据交由业务服务处理，例如工作流接口调用工作流处理逻辑，认证与偏好接口调用认证与偏好服务，历史接口调用历史数据管理逻辑。

4. 服务与数据源接口  
   业务服务通过数据源策略、`mock_store`、偏好服务和数据库访问层组织数据读写。在设计上，后端内部遵循“router -> schema -> service -> data/model”的调用路径。

5. 会话兼容映射接口  
   在工作流和历史模块中，系统支持 `sessionId / id` 的兼容映射处理，用于保证不同调用路径下的会话标识能够统一指向同一业务主线。

6. 统一异常输出接口  
   后端通过统一异常处理机制，将参数错误、资源不存在、任务不存在和内部错误封装为统一错误输出格式，供前端进行统一提示和状态处理。

总体上，内部接口设计遵循“前端页面调用服务层，服务层调用 API 层，API 层访问后端接口，后端再通过路由、服务和数据层完成处理”的协作模式，从而保证系统结构清晰、职责分层明确、前后端协同稳定。
