## 5.4 数据流转设计

本节围绕系统中核心业务数据的流转过程展开说明，重点描述文本、附件、录音、会话状态和任务状态等数据如何在手机端、本地缓存、接口层、后端处理层、持久化层和前端展示层之间流动。与总体结构设计和功能设计不同，本节不强调系统分层或模块职责，而是突出“数据从哪里进入、如何被组织、经过何种处理、写入何处、最终如何回到界面”的完整链路。

结合当前代码仓库实现，系统的数据流转以工作流会话为中心，通过 `sessionId` 串联文本输入、文件上传、录音处理、结果生成、历史沉淀和状态恢复等环节。前端负责数据采集、状态组织和本地缓存，后端负责统一接收请求、处理会话数据、维护任务状态并完成结构化存储，最终再由前端完成结果回填和界面更新。

**图7 数据流转流程图（建议绘制）**  
`文本/文件/音频输入 -> 前端采集与状态组织 -> 工作流 API 接入 -> 后端会话与任务处理 -> 状态同步与持久化 -> 结果回填 -> 工作流界面/历史记录/本地缓存更新`

图中应突出 `sessionId`、`blocks`、`attachments`、`recordedAudio`、`taskId` 等关键数据对象在不同处理层之间的传递关系。整体链路可概括为“输入接入、状态标准化、接口传输、后端处理、状态同步、持久化存储、结果回填”七个阶段，其中普通文本和附件通常在一次请求内完成闭环，长音频则通过异步任务轮询机制持续完成状态更新。

### 5.4.1 输入数据采集与前端组织

系统的数据流转起点为手机端多模态输入。用户可在工作流页面输入文本、选择文件、上传图片或进行录音，前端将这些不同来源的数据统一组织为工作流会话上下文中的状态对象，包括 `sessionId`、`blocks`、`attachments`、`recordedAudio` 以及待处理任务状态等。该设计使不同模态数据能够以一致方式进入后续工作流链路。

在前端组织阶段，文本输入会被构造成用户消息块，附件会先进入待上传列表并维护上传状态，录音数据会形成录音预览或长音频待处理对象。系统同时通过 `WorkflowStorage.loadMessages` 与 `WorkflowStorage.saveMessages` 对会话内容进行本地缓存，从而在页面切换、会话恢复或网络波动场景下保持较好的连续性。

### 5.4.2 接口上传与后端处理

当前端完成数据标准化组织后，相关数据将通过工作流接口上传到后端。前端通过 `workflow-api.ts` 统一调用工作流接口，并使用 `sessionId / id` 兼容映射机制确保不同请求能够指向同一会话上下文。对于文本输入，系统主要通过 `/workflow/input` 和 `/workflow/generate` 完成用户块写入与 AI 结果生成；对于文件输入，系统先通过上传接口形成 `fileRef`，再将文件引用接入工作流；对于音频输入，系统通过音频上传、语音转写或长音频任务接口完成后续处理。

后端围绕工作流会话对数据进行统一处理。`workflow_router.py` 提供了会话获取、输入提交、生成、文件上传、音频上传、转写和长音频任务等接口域，用于承接前端传入的结构化数据。后端处理后的结果可能表现为新的用户块、AI 响应块、文件引用、音频资源标识、转写结果或长任务编号，并统一回送给前端。

### 5.4.3 状态同步与持久化

在数据处理过程中，系统同时维护本地缓存、历史摘要和服务端任务状态三类关键信息。前端在获得新的工作流结果后，会通过 `WorkflowStorage.saveMessages` 将最新 `blocks` 写入本地缓存；同时通过 `History_Storage.saveWorkflowData` 将工作流摘要写入历史记录，以支持后续历史回显和结果复用。该机制使系统具备“本地快速恢复 + 服务端统一处理”的协同特征。

对于后端侧数据，系统通过会话、历史记录和任务状态对象维护主链路信息，并将其写入结构化存储与语义存储中。整体设计可概括为 `PostgreSQL + ChromaDB + 本地缓存` 的组合方式：前端本地缓存负责提升恢复速度和交互连续性，服务端持久化负责保存工作流主线、历史记录、附件引用和语义数据。对于长音频等耗时任务，系统通过 `taskId` 对任务状态进行持续维护，并依赖状态查询接口完成同步。

### 5.4.4 结果回填与界面更新

后端处理完成后，会将相关结果返回前端，包括 `userBlockId`、`aiBlock`、`fileRef`、`remoteAudioId`、`taskId`、任务状态以及会话详情等信息。前端依据这些返回结果更新 `blocks`、附件列表、录音状态、任务状态和历史摘要，使工作流界面中的内容能够连续增长式展示。普通文本与文件输入通常可直接完成结果回填，长音频任务则通过轮询接口持续获取状态，在任务完成后再统一回填到当前会话。

最终，数据流转结果会同时体现在三个位置：一是工作流页面中的即时内容展示，二是历史记录中的摘要更新，三是本地缓存中的会话保存。通过这一设计，系统不仅能够完成单次任务处理，还能够实现历史恢复、继续编辑和跨时段复用，从而形成较完整的移动端 AI 工作流数据闭环。
