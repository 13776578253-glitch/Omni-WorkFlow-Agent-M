## 8 详细设计

本章围绕系统五个核心功能模块的实现方案展开，重点描述模块在运行过程中的状态组织、输入输出关系及核心处理逻辑，从实现层面对系统进行细化说明。

相较于前文的功能划分与总体结构设计，本章聚焦模块内部实现机制，对关键处理流程与调用关系进行展开。各模块程序逻辑统一采用 PDL 方式描述，突出状态判断、接口调用、数据更新与结果回填等核心步骤。系统详细设计包括主界面导航与任务触发、工作流处理、多模态输入、历史会话管理及用户配置与身份管理五个模块，于下文小节8.1至小节8.5所示。

### 8.1 主界面导航与任务触发模块

#### 8.1.1 功能描述

主界面导航与任务触发模块由主布局、首页触发逻辑、历史打开逻辑和工作流注入逻辑共同组成。模块内部的核心任务不是单纯完成页面切换，而是维护当前激活页、当前会话标识、外部待提交输入和工作流重置标记等状态，并将这些状态准确传递给工作流页面。

在实现上，模块通过统一布局组织首页、工作流页与历史页之间的切换，通过会话管理机制维护当前活动会话，并在首页触发或历史恢复时生成并注入待处理输入。整体处理围绕状态切换与上下文传递展开，为后续工作流处理提供统一入口。

#### 8.1.2 性能描述

该模块要求在页面切换、新建工作流、首页触发和历史恢复场景下保持较轻量的状态更新过程。模块初始化时应尽快恢复当前会话标识，切页操作应只修改必要状态，外部输入注入应避免重复提交，历史打开后应能够立即切换到工作流页面并触发后续内容恢复。

#### 8.1.3 输入

- 顶部导航切换事件  
- 首页快捷能力触发文本  
- 首页录音转写结果  
- 历史会话选择事件  
- 当前活动会话 ID  

#### 8.1.4 输出

- 当前激活页索引  
- 当前工作流会话 ID  
- 新建工作流后的会话重置状态  
- 注入工作流页面的外部输入文本  
- 从历史页恢复的目标会话上下文  

#### 8.1.5 程序逻辑

PDL:

初始化：
    读取本地 currentSessionId
    设置 activePage

导航切换：
    接收页面切换事件
    更新 activePage

新建工作流：
    清空 currentSessionId
    生成 resetToken
    跳转至工作流页面

首页输入触发：
    生成 externalInput
    清空 currentSessionId
    设置 submitFlag
    跳转至工作流页面

历史会话恢复：
    接收 sessionId
    更新 currentSessionId
    跳转至工作流页面

工作流触发：
    IF 存在 currentSessionId
        THEN 执行会话恢复流程
    ELSE IF 存在 externalInput
        THEN 构建用户输入并发起任务处理

#### 8.1.6 限制条件

该模块基于移动端单主界面结构设计，围绕多页面导航与工作流上下文切换展开。页面间联动依赖前端状态传递与本地会话管理机制，不涉及全局事件调度或跨端同步能力。

### 8.2 工作流处理模块

#### 8.2.1 功能描述

工作流处理模块是系统的核心模块，负责在单次会话中组织用户输入、结果生成及状态管理。模块围绕会话上下文展开，统一处理文本、附件及语音等多模态输入，并维护消息序列与处理状态。

在实现上，模块首先根据当前会话标识判断处理路径，包括本地恢复、远端补齐或新建会话；随后依据输入类型进入相应处理分支；最终将处理结果统一组织为用户块与结果块，并同步更新会话状态与历史摘要。

模块内部以会话标识与消息序列为主线，确保不同输入场景下的处理流程能够收敛至统一的状态更新与持久化过程。

#### 8.2.2 性能描述

该模块要求在普通文本输入场景下保持快速响应，在历史恢复场景下优先保证本地回显速度，在长音频场景下维持可感知的异步状态反馈。实现上避免整页重置和全量重渲染，优先以局部块更新、会话增量保存和历史摘要同步的方式完成界面刷新。对于远端会话补齐和长任务轮询，模块保持非阻塞式处理，不影响当前页面继续展示已有内容。

#### 8.2.3 输入

- `currentSessionId`、reset token  
- `blocks` 本地缓存内容  
- 用户输入文本  
- 首页传入的 `pendingExternalInput`  
- 附件列表与上传状态  
- 录音预览对象、长录音输入对象  
- 用户偏好配置（预设模式、快捷提示词、长期记忆）  
- 后端返回的会话详情、生成结果、任务状态  

#### 8.2.4 输出

- 更新后的 `blocks` 列表  
- 当前工作流模式 `welcome / document / recording`  
- `fileRef`、`remoteAudioId`、`taskId` 等处理中间结果  
- 最新本地会话缓存  
- 历史摘要中的 `workflowData`  
- 长任务完成后的最终 AI 结果块或回退结果块  

#### 8.2.5 程序逻辑

PDL:

初始化 / 会话加载：
    IF 存在 currentSessionId
        THEN 读取本地消息序列
            IF 本地存在
                THEN 设置 blocks 与页面模式
            ELSE IF 用户已登录
                THEN 从远端加载会话并补齐
    ELSE
        初始化为空会话（欢迎态）

会话重置：
    IF 收到 reset 标记
        THEN 清空 blocks、附件状态、音频状态与任务状态
             重置页面为初始状态

用户输入处理：
    IF 接收到文本或外部输入
        THEN
            IF 不存在有效会话
                THEN 创建新会话并初始化历史摘要
            构建用户消息块并加入 blocks

附件处理：
    IF 输入包含附件
        THEN 先完成文件上传
             将文件引用合并至用户消息

请求生成：
    构建上下文
    调用后端生成接口

结果回填：
    IF 返回成功
        THEN 生成 AI 消息块并替换 pending 状态
    ELSE
        生成 fallback 消息块进行回填

状态持久化：
    blocks 更新后
        同步保存本地会话与历史摘要

语音输入处理：
    IF 为短录音
        THEN 转写为文本并进入用户输入流程
    IF 为长录音
        THEN 提交异步任务并轮询状态
            IF 任务完成
                THEN 拉取结果并更新会话
            ELSE
                回填 fallback 结果

消息编辑与再生成：
    IF 用户编辑已有消息
        THEN 重新构建上下文
             调用生成接口并替换目标结果块

结束状态：
    更新 blocks、页面模式及相关状态
    等待下一次输入或会话切换

#### 8.2.6 限制条件

该模块依赖前端本地存储、工作流 API、历史存储服务和会话管理服务共同工作。普通输入链路以同步回填为主，长音频链路采用异步任务轮询；当远端请求失败、长任务超时或生成失败时，模块会保留本地优先、回退结果和历史摘要同步等技术边界，以保证页面连续可用。当前实现未引入独立任务编排器，所有调度均围绕工作流页面状态和服务调用完成。

### 8.3 多模态输入模块

#### 8.3.1 功能描述

多模态输入模块负责将文本、文件及语音等多种输入形式统一转换为工作流可处理的结构化输入。模块作为输入链路的前置处理单元，不直接参与结果生成，而是为工作流模块提供标准化输入数据。

在实现上，模块根据输入类型选择不同处理路径：文本输入直接形成内容数据，文件输入通过上传获得文件引用，短录音经转写后输出文本，长录音则通过异步任务返回任务标识及处理状态。

模块内部统一维护输入处理状态与异常回退机制，确保不同输入形式能够稳定汇入工作流主线，并在弱网或处理失败场景下保持基本可用。

#### 8.3.2 性能描述

模块要求权限申请、录音采集、文件上传和音频上传流程具备明确状态反馈。实现上应缩短端侧阻塞时间，将高负载处理下放到后端，并通过任务状态或转写结果在较短时间内回传前端。对于长录音链路，应保证任务提交后页面可继续交互，而不是等待本地阻塞处理结束。

#### 8.3.3 输入

- 文本输入内容  
- 文件选择结果、文件名、文件类型、本地路径  
- 录音会话对象、录音模式、录音来源  
- 音频时长、音频 MIME 类型、本地音频路径  
- 当前会话 ID  
- 转写策略与任务提示词  

#### 8.3.4 输出

- 直接可提交的文本内容  
- 上传成功后的 `fileRef`  
- 音频上传成功后的 `remoteAudioId`  
- 短录音转写文本  
- 长录音任务编号 `taskId`  
- 上传状态、录音阶段和任务状态  

#### 8.3.5 程序逻辑

输入分派：
    接收输入事件
    根据输入类型分派至对应处理分支（文本 / 文件 / 短录音 / 长录音）

文本处理：
    IF 输入为文本
        THEN 直接输出文本内容

文件处理：
    IF 输入为文件
        THEN 读取文件信息
             上传文件
             IF 上传成功
                THEN 输出 fileRef
             ELSE 输出错误状态

短录音处理：
    IF 输入为短录音
        THEN 采集音频数据
             上传音频并执行转写
             IF 转写成功
                THEN 输出转写文本
             ELSE 输出回退结果

长录音处理：
    IF 输入为长录音
        THEN 采集并上传音频
             提交异步任务
             IF 提交成功
                THEN 输出 taskId 与任务状态
             ELSE 输出错误状态

结果输出：
    将处理结果统一转换为结构化输入（文本 / fileRef / taskId 等）
    更新前端状态并传递至工作流模块

异常处理：
    IF 任一处理环节失败
        THEN 返回错误状态或回退结果
             由工作流模块决定后续处理策略

#### 8.3.6 限制条件

该模块依赖移动端录音权限、本地文件访问能力以及网络接口可用性。文本链路最轻量，文件和音频链路都依赖后端上传接口；语音理解和长任务处理不在端侧完成，而由后端承担。转写和长录音链路保留策略切换和回退能力，，但不支持完全离线运行。

### 8.4 历史会话管理模块

#### 8.4.1 功能描述

历史会话管理模块负责维护历史摘要列表及相关操作，包括查询、置顶、重命名、删除和会话恢复等功能。模块的核心不在于列表展示，而在于历史数据的组织与状态管理，以及与工作流会话的衔接。

在实现上，模块采用本地优先的数据策略：优先加载本地历史数据，并在满足条件时与远端数据进行同步与补齐；当用户执行删除、置顶或重命名等操作时，先更新本地状态，再进行远端同步；当用户选择历史会话时，将对应会话标识传递至工作流模块以恢复上下文。

#### 8.4.2 性能描述

该模块要求历史列表首屏加载尽量依赖本地数据，避免远端请求阻塞页面展示。搜索操作应以本地过滤为主，保证交互即时响应；重命名、删除和置顶等操作应先完成前端列表更新，再执行远端同步，从而降低感知延迟。历史恢复场景应尽快将目标会话切换到工作流页面。

#### 8.4.3 输入

- 本地历史会话列表  
- 登录用户信息  
- 远端历史接口返回结果  
- 搜索关键词  
- 用户操作指令（打开、删除、置顶、重命名、分享）  
- 目标历史会话 ID  

#### 8.4.4 输出

- 合并后的历史会话列表  
- 过滤后的搜索结果列表  
- 更新后的标题、置顶状态或删除结果  
- 当前会话切换结果  
- 分享构建输入或分享请求结果  

#### 8.4.5 程序逻辑

PDL:
初始化：
    加载本地历史列表
    IF 用户已登录
        THEN 请求远端历史数据
             合并本地与远端列表

搜索处理：
    IF 输入搜索关键词
        THEN 按标题与摘要过滤当前列表

会话恢复：
    IF 用户选择历史会话
        THEN 更新当前会话标识
             跳转工作流页面

列表操作：
    IF 执行重命名 / 删除 / 置顶
        THEN 更新本地列表并持久化
             IF 用户已登录
                THEN 同步远端数据
                     IF 同步失败
                        THEN 保留本地结果

分享处理：
    IF 执行分享操作
        THEN 构建分享内容并触发分享

状态更新：
    刷新列表数据
    保持界面状态与数据一致 

#### 8.4.6 限制条件

该模块依赖本地历史缓存和远端历史接口的协同工作。当前检索逻辑以标题和预览文本过滤为主，不引入独立全文索引；远端同步采用本地优先策略，若网络异常则保留本地结果。历史分享能力以现有会话内容构建为主，不涉及独立导出格式编排引擎。

### 8.5 用户配置与身份管理模块

#### 8.5.1 功能描述

用户配置与身份管理模块负责维护用户认证状态、基础信息及个性化配置，并管理本地状态与服务端数据之间的同步关系。模块的核心不在于单次登录或配置操作，而在于保证用户身份与偏好数据在应用重启后能够稳定恢复，并在登录状态下实现一致性维护。

在实现上，模块包含认证管理与偏好管理两个子部分：认证管理负责用户登录、注册及状态更新，并维护本地登录状态；偏好管理负责个性化配置的读取与保存，并在满足条件时与服务端进行同步。相关配置在工作流处理中被读取并参与上下文构建，从而影响后续处理结果。

#### 8.5.2 性能描述

该模块要求认证状态读取轻量、登录结果反馈直接、偏好回显优先使用本地数据。实现上应尽量避免进入用户页面后必须等待远端返回才能展示已有配置；保存偏好时应先写本地再进行远端同步，以保证界面稳定和修改结果可见。认证成功后应及时写入本地身份状态，供其他页面读取。

#### 8.5.3 输入

- 手机号、昵称、密码、验证码  
- 本地认证状态对象  
- 本地偏好配置对象  
- 用户修改后的预设模式、快捷提示词、长期记忆内容  
- 远端认证接口返回结果  
- 远端偏好接口返回结果  

#### 8.5.4 输出

- 当前登录状态  
- 用户身份信息  
- 本地保存后的偏好配置  
- 服务端同步后的偏好结果  
- 工作流模块可读取的用户配置上下文  

#### 8.5.5 程序逻辑

PDL:
认证状态初始化：
    读取本地认证状态
    根据状态展示对应页面（登录 / 注册 / 已登录）

认证处理：
    IF 执行登录 / 注册 / 验证等操作
        THEN 调用认证接口
             IF 成功
                THEN 更新本地认证状态

偏好初始化：
    读取本地偏好配置并完成页面回显
    IF 用户已登录
        THEN 请求远端配置并覆盖本地数据

偏好修改：
    IF 用户修改配置
        THEN 更新本地状态并持久化
             IF 用户已登录
                THEN 同步远端数据
                     IF 同步失败
                        THEN 保留本地结果

上下文提供：
    工作流模块读取本地认证状态与偏好配置
    作为后续处理的上下文输入
#### 8.5.6 限制条件

该模块面向移动端单用户场景设计，重点保障认证状态与偏好配置的本地持久化及与服务端的一致性同步。未登录状态下数据仅保存在本地，登录后再进行远端同步。当前设计不涉及多用户权限体系、协作场景或配置版本管理等复杂机制。
